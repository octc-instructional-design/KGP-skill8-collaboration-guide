Section 8.1

Using Blackboard for Group Work

Not a how-to-click-Blackboard guide — the group-work decisions, dependencies, and boundaries that the step-by-step articles won't make for you.

What to Use, What Order to Do It In, What Bites

This page assumes you can find your way around Blackboard and know how to reach support — so it skips the click-by-click steps (which change with every update anyway) and covers only what's specific to running group work: which feature fits which job, the order things have to happen in, the settings that cause real pain when they're wrong, and the boundaries worth telling students up front. For current steps, the support link at the bottom is always more up to date than a screenshot would be.

Note the pattern in rows two through four: groups aren't something you create inside a discussion or an assignment. You build the set once, centrally, and then attach it wherever you need it.

The Order This Has to Happen In

Most group-work setup trouble is an ordering problem, not a settings problem. Do it in this sequence and the rest goes smoothly.

  1. Create the group set in Groups first. Groups is its own top-level item in the course, alongside your content. You cannot create a set from inside a discussion or assignment — it has to exist before you go looking for it there.
  2. Choose the enrollment method as you build the set — manual, random, or self-enrollment. For a sustained project, assign manually using the Collaboration Profile Survey in 7.0; that's the fairest and lets you plan around attrition. Self-enrollment is fine for low-stakes activities; random risks lopsided teams.
  3. Make the group set visible to students in Groups. This is the step that catches people. See the warning below.
  4. Now create the discussion or assignment and attach the set. It will appear as an option only once steps 1 and 3 are done.

If a group set isn't marked visible in Groups, it will not appear as a choice when you set up a Group Discussion — your only option is “No,” and nothing on that screen tells you why. If the set you just built isn't listed, go back to Groups and check its visibility before you rebuild anything.

Settings That Actually Bite

  • Graded or ungraded. Decide before you create the item — a graded discussion or assignment creates a gradebook column. Quick activities usually stay ungraded and fold into participation.
  • Group grading defaults to the same grade for everyone. Know that you can override individual grades when contributions differ, and pair that with a peer evaluation rather than deciding on impression.
  • Availability and due dates. Set them on the item, then use Student Preview to confirm that groups, dates, and the rubric all display the way you expect before you release it.
  • Editing group membership mid-project. Changing membership after submissions have started can orphan a team's work. Lock your groups once the project is underway; if you must move someone, check what happens to what they've already submitted.
  • Attach the rubric to the assignment itself so students see how they'll be scored before they submit, not after.

Boundaries & Gotchas

Blackboard is the official record. Teams is the workspace. Every graded deliverable submits here — not by email, not as a Teams file. Say so on day one.

  • Run Student Preview before releasing anything group-related. It's the cheapest way to catch a broken setup before a student does.
  • If a team works in Teams, the finished work still comes back to Blackboard for the grade. The workspace and the record are different places on purpose.
  • Hidden parent, hidden children. If the folder holding your group activity is hidden from students, nothing inside it is visible either — regardless of what the individual items say.
